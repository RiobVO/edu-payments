# Учёт оплат учебного центра

Тестовое задание Ecomdev. Внутри API для учеников, оплат и должников и веб-страница для телефона (вариант Б).

На странице:

- карточка месяца: сколько осталось получить и сколько собрано от начислений; месяцы листаются стрелками;
- должники с суммой остатка и шкалой «внесено / недостаёт» у каждого;
- переключатель «Должники / Все ученики»: у оплативших шкала заполнена, у записанных на будущее видно, с какого числа они учатся;
- карточка ученика по тапу: долг за месяц, история оплат, кнопка звонка, изменение и удаление с подтверждением;
- форма оплаты: ученик и сумма долга подставляются сами, дата по умолчанию сегодняшняя;
- форма «+ Ученик» с датой «Учится с», от которой считаются долги;
- на широком экране слева список групп: у каждой видно, сколько учеников должны и на какую сумму, клик фильтрует таблицу.

## Запуск с нуля

Нужен Node.js 22.13 или новее, лучше 24 LTS. Docker и отдельная БД не нужны: данные хранятся в SQLite-файле `data/payments.db`, он создаётся сам при первом запуске.

```bash
git clone https://github.com/RiobVO/edu-payments.git
cd edu-payments
npm ci
npm run build
npm run seed     # необязательно: 9 демо-учеников с оплатами за прошлый и текущий месяц
npm start        # страница и API на http://localhost:3000
```

Проверки:

```bash
npm test             # 64 теста: API, расчёт долгов, валидация, отдача страницы
npm run typecheck
```

Открыть страницу с телефона в той же Wi-Fi-сети можно так: запустить `HOST=0.0.0.0 npm start` и зайти на `http://<IP компьютера>:3000`.

На Node 22 при старте появится `ExperimentalWarning: SQLite is an experimental feature`. Так и должно быть, на Node 26 этого предупреждения нет. CI гоняет тесты на Node 22.13, 24 и 26.

| Переменная  | По умолчанию       | Зачем                                              |
|-------------|--------------------|----------------------------------------------------|
| `PORT`      | `3000`             | порт                                               |
| `HOST`      | `127.0.0.1`        | `0.0.0.0`, чтобы открыть доступ из локальной сети  |
| `DB_PATH`   | `data/payments.db` | путь к файлу базы                                  |
| `TIME_ZONE` | `Asia/Tashkent`    | по этому поясу определяются «сегодня» и «текущий месяц» |

## API

| Метод    | Путь                       | Что делает                                       |
|----------|----------------------------|--------------------------------------------------|
| `POST`   | `/students`                | создать ученика                                  |
| `GET`    | `/students`                | список учеников по алфавиту                      |
| `GET`    | `/students/:id`            | один ученик                                      |
| `PATCH`  | `/students/:id`            | изменить любые из полей                          |
| `DELETE` | `/students/:id`            | удалить ученика вместе с его оплатами            |
| `POST`   | `/students/:id/payments`   | добавить оплату                                  |
| `GET`    | `/students/:id/payments`   | оплаты ученика, сначала новые                    |
| `GET`    | `/debtors?month=YYYY-MM`   | должники за месяц; без `month` — за текущий     |
| `GET`    | `/config`                  | часовой пояс центра для страницы                 |

Неверные данные возвращают `400` с описанием поля, несуществующий ученик — `404`. Проверка строгая: `"500000"` вместо числа, `true` или неизвестное поле (например, опечатка `monthly_fee`) тоже дают `400`, а не тихо приводятся или пропускаются.

```bash
# ученик: имя, телефон, группа, сумма в месяц (целое число, сумы);
# startDate — с какого дня учится, необязательно (по умолчанию сегодня)
curl -X POST localhost:3000/students -H 'Content-Type: application/json' \
  -d '{"name":"Азиз Каримов","phone":"+998 90 123-45-67","group":"English B1","monthlyFee":500000,"startDate":"2026-09-01"}'

curl -X PATCH localhost:3000/students/1 -H 'Content-Type: application/json' -d '{"monthlyFee":550000}'

# оплата: без date ставится сегодняшняя дата
curl -X POST localhost:3000/students/1/payments -H 'Content-Type: application/json' \
  -d '{"amount":200000,"date":"2026-10-05"}'

curl localhost:3000/students/1/payments
curl 'localhost:3000/debtors?month=2026-10'
```

```json
{
  "month": "2026-10",
  "totalDebt": 350000,
  "debtors": [
    {
      "studentId": 1,
      "name": "Азиз Каримов",

      "group": "English B1",
      "monthlyFee": 550000,
      "paid": 200000,
```

## Как считается долг

- Долг за месяц — это месячная сумма минус оплаты, дата которых попадает в этот месяц. Несколько оплат складываются.
- Ученик без единой оплаты за месяц попадает в должники на всю сумму.
- Кто заплатил ровно или больше, тот не должник. Переплата на следующий месяц не переносится.
- Кто начал учиться после выбранного месяца (поле `startDate`), за него не должен. Начавший в середине месяца должен полную сумму.
- «Сегодня» и «текущий месяц» считаются по Ташкенту. Оплата, внесённая 1-го числа в 01:00, относится к новому месяцу, хотя по UTC это ещё предыдущий.
- В списке сначала идут самые большие долги.

## Решения

- Суммы хранятся целыми числами в сумах, float нигде нет. Копейки у сума на практике не используются, а float в деньгах даёт ошибки округления.
- База — SQLite через встроенный `node:sqlite`. Нативных модулей, которые нужно компилировать при `npm ci`, нет.
- Оплату с будущей датой API не примет: это почти всегда опечатка, которая молча закрыла бы долг не того месяца. Несуществующую дату вроде 30 февраля тоже.
- При удалении ученика удаляются и его оплаты (`ON DELETE CASCADE`). Для настоящего центра лучше архив, об этом в списке улучшений.
- Страница сделана без фреймворка и сборки. Данные выводятся через `textContent`, поэтому имя ученика не может внедрить на страницу HTML или скрипт. Шрифт Inter лежит в репозитории (лицензия OFL), фон карточки месяца — свой SVG, сторонних запросов страница не делает.

## Структура

```
src/
  app.ts        сборка Fastify-приложения, зависимости передаются явно (база, часы)
  students.ts   CRUD учеников
  payments.ts   оплаты
  debtors.ts    расчёт должников (один SQL-запрос)
  db.ts         схема SQLite
  time.ts       даты в часовом поясе центра
  server.ts     точка входа
  seed.ts       демо-данные
public/         страница: index.html, styles.css, app.js
test/           тесты Vitest через fastify.inject, без поднятия сервера
```

## Что бы я улучшил, будь у меня ещё неделя

1. Авторизация. Сейчас API открыт любому, кто достучится до порта, а речь идёт о деньгах. Нужен вход для сотрудников и роли: администратор вносит оплаты, владелец смотрит отчёты.
2. Месяц оплаты отдельно от даты. Сейчас оплата засчитывается в месяц своей даты. Если ученик в октябре гасит сентябрьский долг, деньги уйдут в октябрь. Нужно поле «за какой месяц» и перенос переплаты на следующие месяцы.
3. История тарифов. Если поменять месячную сумму, пересчитаются и долги за прошлые месяцы. Нужна таблица тарифов с датой начала действия, а для тех, кто начал в середине месяца, — расчёт пропорционально дням.
4. Архив вместо удаления и отмена ошибочной оплаты. Ушедший ученик остаётся в архиве со всей историей, ошибочную оплату можно отменить с указанием причины, все изменения пишутся в журнал.
5. Telegram-бот (вариант А) поверх того же API, напоминания должникам и e2e-тест страницы в CI.
